\begin{abstract}
Federated learning (FL) over wireless edge networks suffers from the mismatch between large-scale model updates and time-varying communication resources.  While Mixture-of-Experts (MoE) models achieve scalable capacity through sparse activation, each client still update many experts during local training, leading to substantial wasted computation when only a limited subset of expert updates can be uploaded. To address this challenge, we propose PCASE, a Proactive Channel-Aware Sparse Expert aggregation framework for federated MoE learning under constrained wireless communication budgets. To address these challenges, we propose PCASE, a Proactive Channel-Aware Sparse Expert aggregation framework for federated MoE learning under constrained wireless communication budgets. Unlike post-hoc sparse upload methods, PCASE accounts for communication constraints prior to local training and trains only a budget-feasible subset of experts. Each client performs lightweight forward-pass probing to estimate local expert utilities and constructs empirical Bernstein confidence intervals to balance probing latency and selection reliability. Under the current communication budget, each client employs a dynamic programming oracle to identify a high-utility feasible subset of experts, while a single-swap confidence criterion enables efficient reliability verification without exhaustively enumerating all feasible subsets. The server then performs sparse expert-wise aggregation over the selected experts and applies FedAvg to shared parameters.

\section{Introduction}

Federated learning (FL) enables edge clients to collaboratively train a model without exposing raw data, making it attractive for wireless edge intelligence across mobile devices. However, wireless FL is inherently constrained by time-varying uplink channels, heterogeneous client resources, and non-independent and identically distributed (non-IID) data. In each communication round, a client can upload only a limited number of bits determined by its instantaneous channel state, power budget, bandwidth allocation, and latency requirement. As foundation models continue to scale, this mismatch between model size and wireless uplink capacity becomes a fundamental bottleneck.

Mixture-of-Experts (MoE) models offer a promising way to scale model capacity through conditional computation. By routing each input to only a small subset of experts, MoE models can maintain large parameter capacity while activating only part of the model per sample. This sparse structure is particularly appealing for federated learning, where different clients may favor different experts according to their local data distributions. Nevertheless, wireless federated MoE learning faces a unique communication-computation mismatch: although each input activates only a few experts, local training over multiple mini-batches may generate updates for many experts, while the client may only be able to upload a small subset of them under its current uplink budget.

Existing communication-efficient FL methods typically follow a post-hoc sparse upload paradigm. The client trains all routed experts locally but transmits only a budget-feasible subset of expert updates afterwards. While this reduces the number of uploaded bits, it does not prevent redundant computation. If an expert is updated locally but eventually not transmitted, its backpropagation, optimizer update, and memory usage do not directly contribute to global aggregation. This inefficiency becomes increasingly severe when the uplink budget is small, the number of experts is large, or local devices are burdened by concurrent application workloads.

To reduce unnecessary local computation, our key insight is that instead of treating the wireless channel as a post-training upload constraint, we inject the channel condition before local backpropagation and select a subset of experts for training. An MoE model already provides informative expert-preference signals before full local training. By running a small number of forward-only probing mini-batches, each client estimates the local utility of every expert using the average utility over the tokens in each probing mini-batch. Moreover, since the router typically computes scores for all experts before sparse dispatching, a single probing pass can produce feedback over the entire expert pool. This allows the client to compare multiple candidate expert subsets before committing computational resources to local optimization.

However, this idea introduces two key challenges. The first is latency--reliability tradeoff in expert utility estimation. Estimating expert utilities over the entire local dataset can provide accurate client-specific preference information, but it incurs excessive probing latency and computation overhead on resource-constrained edge devices. In contrast, relying on only a few probing mini-batches substantially reduces overhead, but may lead to unstable expert selection, especially under non-IID data distributions. The second is combinatorial certification complexity. To rigorously verify whether the selected expert subset is superior to all other feasible subsets, a client would need to compare it against every subset satisfying the current uplink constraint. Since the number of feasible expert subsets grows exponentially with the number of experts, exhaustively evaluating them leads to excessive computational overhead and latency.

To address these challenges, we propose PCASE, a Proactive Channel-Aware Sparse Expert aggregation framework for federated MoE learning under constrained communication budgets. PCASE proactively selects a high-utility expert subset for each client under the current communication budget, thereby reducing redundant expert training while preserving client-specific expert specialization. For balancing latency and reliability in expert utility estimation, PCASE incrementally estimates expert utilities of each client using lightweight probing mini-batches that require only forward passes. It then constructs empirical-Bernstein confidence intervals to adapt the probing effort to estimation uncertainty. Given the estimated utilities and the current communication budget, the client employs a dynamic programming oracle to select a subset of experts and trains only the selected experts. For reducing combinatorial certification complexity, PCASE further introduces a local confidence criterion based on feasible single-swap alternatives, avoiding exhaustive enumeration over all feasible subsets while retaining a practical reliability check for each client’s selected expert set. After local training, PCASE performs server-side sparse expert-wise aggregation, in which each expert is updated using only the parameter uploaded by clients that selected that expert, while the shared parameters are aggregated via standard FedAvg.

\subsection{System Model}

Federated learning (FL) is a distributed collaborative training paradigm in which multiple clients jointly learn a shared global model without exposing their raw data to the server. Federated learning proceeds iteratively between local training on edge clients and model aggregation on the server. In each communication round, the server first distributes the current global model to the clients participating in training. Then, each client trains its local model using its private local data and uploads the local model parameters or model updates to the server. After receiving updates from multiple clients, the server generates a new global model according to the aggregation strategy and sends it back to the clients for the next round of training. Let $\mathcal{I}=\left \{ 1,2,\dots ,n \right \} $ denote the set of participating clients, and let $\mathcal{D}_i$ be the local dataset of client $i$. The global objective is to minimize a weighted empirical risk over all clients:
\begin{equation}
\min_{\boldsymbol{\theta}} F(\boldsymbol{\theta})
=
\sum_{i\in\mathcal{I}}
\frac{n_i}{n}
F_i(\boldsymbol{\theta}),
\quad
n=\sum_{i\in\mathcal{I}} n_i ,
\end{equation}
where $F_i(\boldsymbol{\theta})$ denotes the empirical loss evaluated on $\mathcal{D}_i$. 

Mixture-of-Experts (MoE) models use multiple expert modules and a gating network to enable conditional computation. For each input, the gate assigns routing weights to experts, allowing expert specialization and increasing the effective model capacity. In FL, MoE can naturally accommodate heterogeneous client data distributions. For client $i$ at communication round $r$, the gating output of the $\ell$-th MoE layer for input $x$ is defined as
\begin{equation}
\mathbf{g}_{i,\ell}^{(r)}(x)
=
\bigl(
g_{i,\ell,1}^{(r)}(x),
\ldots,
g_{i,\ell,e_\ell}^{(r)}(x)
\bigr),
\end{equation}
where $g_{i,\ell,j}^{(r)}(x)$ represents the gating weight assigned to expert $j$ among the $e_\ell$ experts in the $\ell$-th MoE layer. For simplicity, we assume that $g_{i,\ell,j}^{(r)}(x)$ has been normalized within each MoE layer, and use $g_{i,j}^{(r)}(x)$ to denote the gating weight assigned to the $j$-th expert module of client $i$.

%=========================================
We study an edge FL framework for training a MoE model over edge clients with heterogeneous local data distributions and limited uplink communication resources. Due to the uplink transmission budget $B_i^{(r)}$, client $i$ is allowed to upload only a subset of expert parameters in communication round $r$. Let $\mathcal{E}=\{1,2,\ldots,n_e\}$ denote the set of expert modules, where $n_e$ is the total number of experts. For each client $i$, our objective is to find a feasible set of experts that satisfies the uplink communication budget while maximizing the local expert utilization:
\begin{equation}
\label{optimization objective}
\begin{aligned}
\max_{\mathcal{S}\subseteq \mathcal{E}}
\quad &
\sum_{j\in \mathcal{S}}\mu_{i,j}^{(r)}
\\
\mathrm{s.t.}
\quad
&
\sum_{j\in \mathcal{S}} c_j + c_{\rm sh}
\le B_i^{(r)} ,
\end{aligned}
\end{equation}
where $\mu_{i,j}^{(r)}=\mathbb{E}_{x\sim\mathcal{D}_i}[g_{i,j}^{(r)}(x)]$ denotes the expected utilization of expert $j$ by client $i$, $c_j$ denotes the upload cost of expert $j$, and $c_{\rm sh}$ denotes the upload cost of the shared parameters. By introducing a binary selection variable $z_{i,j}^{(r)}$, Eqn.~\eqref{optimization objective} can be equivalently formulated as a 0-1 knapsack problem:
\begin{equation}
\label{eq:knapsack_general}
\begin{aligned}
\max_{\{z_{i,j}^{(r)}\}_{j=1}^{n_e}}
\quad &
\sum_{j=1}^{n_e} z_{i,j}^{(r)} \mu_{i,j}^{(r)}
\\
\mathrm{s.t.}
\quad &
\sum_{j=1}^{n_e} z_{i,j}^{(r)} c_j
\le C_i^{(r)},
\\
&
z_{i,j}^{(r)}\in\{0,1\},
\quad j=1,\ldots,n_e ,
\end{aligned}
\end{equation}
where $C_i^{(r)} = B_i^{(r)} - c_{\rm sh}$. 

\subsection{Adaptive Channel-Aware Expert Uploading}
\label{subsec:proactive_channel_aware}
Solving the knapsack problem in Eqn.~\eqref{eq:knapsack_general} requires each client to obtain the expected utilization $\mu_{i,j}^{(r)}$ of every expert at each communication round. Although the exact value of $\mu_{i,j}^{(r)}$ offers a precise characterization of client-specific expert preferences, evaluating it over the entire local dataset incurs significant computational overhead and latency on resource-constrained edge clients, especially when such evaluation is performed repeatedly across rounds. To reduce this overhead, we propose an adaptive channel-aware expert uploading mechanism in \xxx, which incrementally estimates expert utilizations from probe mini-batches and employs a lightweight DP oracle to determine the expert set to upload in the current round.

Specifically, let $Y_{i,j,m}^{(r)}$ denote the observed utilization of expert $j$ at probing step $m$. It is computed as the average normalized gating weight assigned to expert $j$ over the samples in the probing mini-batch:
\begin{equation}
Y_{i,j,m}^{(r)}
=
\frac{1}{|\mathcal{B}_{i,m}^{(r)}|}
\sum_{x\in \mathcal{B}_{i,m}^{(r)}}
g_{i,j}^{(r)}(x),
\end{equation}
where $\mathcal{B}_{i,m}^{(r)} \subseteq \mathcal{D}_i$ denotes the probing mini-batch sampled at probing step $m$. By randomly sampling $\mathcal{B}_{i,m}^{(r)}$ from the local dataset $\mathcal{D}_i$, $Y_{i,j,m}^{(r)}$ provides an unbiased estimate of the expected expert utilization $\mu_{i,j}^{(r)}$. Client $i$ then computes the empirical utilization estimate
\begin{equation}
\widehat{\mu}_{i,j}^{(r)}(m)
=
\frac{1}{m}
\sum_{b=1}^{m} Y_{i,j,b}^{(r)} ,
\end{equation}
and the corresponding confidence interval is given by
\begin{align}
L_{i,j}^{(r)}(m)
&=
\widehat{\mu}_{i,j}^{(r)}(m)
-
\beta_{i,j}^{(r)}(m),
\\
U_{i,j}^{(r)}(m)
&=
\widehat{\mu}_{i,j}^{(r)}(m)
+
\beta_{i,j}^{(r)}(m),
\end{align}
where $\beta_{i,j}^{(r)}(m)$ is the confidence radius. Unlike Hoeffding-type radii~\cite{auer2002finite}, UCB-V-style empirical Bernstein radii~\cite{audibert2009exploration} adapt to the empirical variance of each expert, yielding tighter bounds for low-variance experts while maintaining sufficient exploration for high-variance ones. Accordingly, we use the following empirical-Bernstein confidence radius:
\begin{equation}
\beta_{i,j}^{(r)}(m)
=
\sqrt{
\frac{
2\widehat{\sigma}_{i,j}^{(r)}(m)\log m
}{m}
}
+
\frac{3\log m}{m},
\end{equation}
where $\widehat{\sigma}_{i,j}^{(r)}(m)$ is the empirical variance of 
$\{Y_{i,j,b}^{(r)}\}_{b=1}^{m}$. 

The resulting empirical estimates are then used as surrogate utilities to determine the set of experts uploaded under the current uplink budget. Let $V_{i,m}^{(r)}(j,q)$ denote the maximum empirical utility obtained byselecting a subset from the first $j$ experts under upload budget $q$, where $q=0,1,\ldots,C_i^{(r)}$. The candidate empirical utility associated with including expert $j$ under budget $q$ is defined as
\begin{equation}
\label{eq:dp_take_value_xxx}
T_{i,m}^{(r)}(j,q)
=
V_{i,m}^{(r)}(j-1,q-c_j)
+
\widehat{\mu}_{i,j}^{(r)}(m),
\end{equation}
and the DP recursion is then given by
\begin{equation}
\label{eq:dp_recursion_empirical_xxx}
V_{i,m}^{(r)}(j,q)
=
\begin{cases}
V_{i,m}^{(r)}(j-1,q), & q<c_j,\\
\max\{V_{i,m}^{(r)}(j-1,q),T_{i,m}^{(r)}(j,q)\}, & q\geq c_j ,
\end{cases}
\end{equation}
with initialization $V_{i,m}^{(r)}(0,q)=0$, for $q=0,1,\ldots,C_i^{(r)}$. 

The selected empirical expert subset $\widehat{\mathcal{S}}_{i,m}^{(r)}$ is recovered by traversing the DP table in reverse and inferring the inclusion decisions from the optimal value differences. With the initial state $(j,q)=(n_e,C_i^{(r)})$, expert $j$ is selected if
\begin{equation}
\label{eq:dp_backtracking_condition_xxx}
V_{i,m}^{(r)}(j,q)
\neq
V_{i,m}^{(r)}(j-1,q),
\end{equation}
in which case the remaining budget is updated as
\begin{equation}
\label{eq:dp_backtracking_budget_update_xxx}
q \leftarrow q-c_j .
\end{equation}
Otherwise, expert $j$ is not selected. In either case, the index is decremented as $j \leftarrow j-1$, and the backtracking continues until $j=0$.

After obtaining the current empirical expert subset 
$\widehat{\mathcal{S}}_{i,m}^{(r)}$, client $i$ evaluates whether the subset is sufficiently reliable under the current confidence intervals. Ideally, such reliability could be certified by comparing $\widehat{\mathcal{S}}_{i,m}^{(r)}$ against the best alternative expert subset that satisfies the uplink budget constraint. Nevertheless, when the uplink budget is not highly restrictive, the feasible subset family can be exponentially large in the number of experts, making subset-level certification computationally prohibitive during probing. Therefore, we propose a local confidence certification criterion based on feasible single-swap alternatives in \xxx. Specifically, let $\mathcal{F}_i^{(r)}$ denote the collection of all feasible expert subsets under the current uplink budget:
\begin{equation}
\label{eq:feasible_subset_family_xxx}
\mathcal{F}_i^{(r)}
=
\left\{
\mathcal{S}\subseteq \mathcal{E}
:
\sum_{j\in\mathcal{S}} c_j
\leq C_i^{(r)}
\right\}.
\end{equation}
The lower-confidence utility of the current empirical subset is defined as
\begin{equation}
\label{eq:selected_subset_lcb_xxx}
\mathrm{LCB}_{i,m}^{(r)}
\left(
\widehat{\mathcal{S}}_{i,m}^{(r)}
\right)
=
\sum_{j\in \widehat{\mathcal{S}}_{i,m}^{(r)}}
L_{i,j}^{(r)}(m).
\end{equation}
For any feasible subset $\mathcal{S}\in \mathcal{F}_i^{(r)}$, its upper-confidence utility is defined as
\begin{equation}
\label{eq:competing_subset_ucb_xxx}
\mathrm{UCB}_{i,m}^{(r)}(\mathcal{S})
=
\sum_{j\in \mathcal{S}}
U_{i,j}^{(r)}(m).
\end{equation}

Instead of comparing the current solution with all feasible subsets in $\mathcal{F}_i^{(r)}$, \xxx only considers its feasible single-swap neighborhood. For any selected expert $a\in\widehat{\mathcal{S}}_{i,m}^{(r)}$ and any unselected expert $b\in\mathcal{E}\setminus\widehat{\mathcal{S}}_{i,m}^{(r)}$, define
\begin{equation}
\label{eq:single_swap_subset_xxx}
\mathcal{S}_{a,b}
=
\widehat{\mathcal{S}}_{i,m}^{(r)}
\setminus \{a\}
\cup \{b\}.
\end{equation}
Then, the feasible single-swap neighborhood is given by
\begin{equation}
\label{eq:single_swap_neighbor_xxx}
\mathcal{N}
\left(
\widehat{\mathcal{S}}_{i,m}^{(r)}
\right)
=
\left\{
\mathcal{S}_{a,b}
:
\mathcal{S}_{a,b}\in\mathcal{F}_i^{(r)}
\right\},
\end{equation}
where $a$ and $b$ range over
$a\in\widehat{\mathcal{S}}_{i,m}^{(r)}$ and
$b\in\mathcal{E}\setminus\widehat{\mathcal{S}}_{i,m}^{(r)}$, respectively.
The probing process terminates if
\begin{equation}
\label{eq:single_swap_stop_xxx}
\mathrm{LCB}_{i,m}^{(r)}
\left(
\widehat{\mathcal{S}}_{i,m}^{(r)}
\right)
>
\max_{\mathcal{S}\in
\mathcal{N}
\left(
\widehat{\mathcal{S}}_{i,m}^{(r)}
\right)}
\mathrm{UCB}_{i,m}^{(r)}(\mathcal{S}),
\end{equation}
or if the maximum probing budget $M_{\max}$ is reached. Subsequently, once the stopping criterion is satisfied, only the experts selected in $\widehat{\mathcal{S}}_{i,m}^{(r)}$ participate in local training and upload their updates to the server in the current round, whereas the remaining experts are excluded from training.

\subsection{Expert-Wise Sparse Expert Aggregation}
\label{subsec:expert_sparse_aggregation}

Given the client-specific expert subsets uploaded to the server, \xxx performs sparse expert-wise aggregation by updating each expert only with local updates from the corresponding clients, while aggregating the shared parameters using FedAvg~\cite{mcmahan2017communication}. For each expert $j$, we define the set of clients uploading its update in communication round $r$ as
\begin{equation}
\label{eq:client_set_expert}
\mathcal{I}_j^{(r)}
=
\left\{
i\in\mathcal{I}:
j\in
\widehat{\mathcal{S}}_{i,m}^{(r)}
\right\},
\end{equation}

The server aggregates expert $j$ only over the clients in $\mathcal{I}_j^{(r)}$, rather than treating the missing expert updates from other clients as zero updates. Let $\Delta_{i,j}^{(r)}$ denote the local update of expert $j$ uploaded by client $i$ in round $r$, where $i\in\mathcal{I}_j^{(r)}$. The sparse aggregated update for expert $j$ is computed as
\begin{equation}
\label{eq:expert_sparse_agg}
\Delta_j^{(r)}
=
\frac{
\sum_{i\in\mathcal{I}_j^{(r)}}
n_{i,j}^{(r)}
\Delta_{i,j}^{(r)}
}{
\sum_{i\in\mathcal{I}_j^{(r)}}
n_{i,j}^{(r)}
},
\qquad
\mathcal{I}_j^{(r)}\ne\varnothing .
\end{equation}
where $n_{i,j}^{(r)}$ denote the number of tokens routed to and processed by expert $j$ during client $i$'s local training in round $r$. After obtaining $\Delta_j^{(r)}$, the server updates the global parameters of expert $j$ as
\begin{equation}
\label{eq:expert_update}
\boldsymbol{\theta}_{j}^{(r+1)}
=
\boldsymbol{\theta}_{j}^{(r)}
+
\eta_{\rm g}
\Delta_j^{(r)},
\qquad
\mathcal{I}_j^{(r)}\ne\varnothing ,
\end{equation}
where $\eta_{\rm g}$ is the server-side update step size. If $\mathcal{I}_j^{(r)}=\varnothing$, the corresponding expert parameters remain unchanged:
\begin{equation}
\label{eq:expert_no_update}
\boldsymbol{\theta}_{j}^{(r+1)}
=
\boldsymbol{\theta}_{j}^{(r)}.
\end{equation}

Since all clients train and upload the shared parameters, the server updates the shared parameters via FedAvg over the participating clients. Let $\Delta_{{\rm sh},i}^{(r)}$ denote the shared parameter update uploaded by client $i$. The aggregated shared update is computed as
\begin{equation}
\label{eq:shared_agg}
\Delta_{\rm sh}^{(r)}
=
\frac{
\sum_{i\in\mathcal{I}}
n_i
\Delta_{{\rm sh},i}^{(r)}
}{
\sum_{i\in\mathcal{I}}
n_i
},
\end{equation}
where $n_i=|\mathcal{D}_i|$ denotes the local dataset size of client $i$. The global shared parameters are then updated by
\begin{equation}
\label{eq:shared_update}
\boldsymbol{\theta}_{\rm sh}^{(r+1)}
=
\boldsymbol{\theta}_{\rm sh}^{(r)}
+
\eta_{\rm g}
\Delta_{\rm sh}^{(r)} .
\end{equation}

Finally, the updated shared parameters $\boldsymbol{\theta}_{\rm sh}^{(r+1)}$ and expert parameters $\{\boldsymbol{\theta}_{j}^{(r+1)}\}_{j=1}^{n_e}$ are assembled into the updated global MoE model, which is then broadcast to all clients in the next communication round.
